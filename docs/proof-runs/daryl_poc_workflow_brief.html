Proof of Concept

IBD Game Scan: End-to-End Workflow

This version proves that Shauna can download market data, run the same pipeline across multiple reporting periods, and produce meeting-ready game launch briefs with mobile-first logic plus curated news context.

What This Proves

The system is not hardcoded to one week. Different Sensor Tower, SteamDB, and Game News Radar inputs produce different report outputs while applying the same rules: released games must fall inside the report period, news must be posted inside the report period, and PC-only games do not show fake SG mobile performance.

Workflow Layers

1

Mobile Discovery

Manual input: Shauna downloads Sensor Tower revenue and SG chart exports. The script finds mobile games with SG/SEA revenue and rank evidence.

2

PC Discovery

Manual input: Shauna saves SteamDB release pages. The script finds strong PC releases and checks mobile candidates for PC equivalents.

3

Game Layer

The system combines mobile and PC evidence into one game-level layer: mobile-only, mobile-led with PC version, or PC-only.

4

Enrichment

Shauna/Codex adds researched genre, publisher/developer, platforms, release date, and two-sentence game summary for report-facing titles.

5

News Context

Game News Radar provides wide-net story candidates. Only reviewed, high-score, in-period announcements enter the final brief.

6

Final Brief

The static report separates Mobile Games, Mobile + PC Games, and PC-only Games, then exports HTML, JSON, and CSV.

Manual Work vs Automation

  • Manual: download Sensor Tower exports, save SteamDB pages, review final news candidates, and add researched enrichment for report-facing titles.
  • Automated: parse inputs, rank/filter candidates, merge mobile/PC evidence, enforce report-period rules, generate final HTML/JSON/CSV.
  • Still to automate: enrichment queue and a real archive page that lists proof/final briefs automatically. Historical run packaging is now available through scripts/run_historical_proof.py.
